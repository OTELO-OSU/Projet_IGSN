# iSamples Core 2.0 as a third `/service` read format

## Context

`GET /service/samples` and `GET /service/samples/:igsn` serve IGSN Core by default and DataCite 4.7 under `application/vnd.otelo.datacite+json` (PR #228, ADR 0042). The signed contract `Mapping_implementation_IGSN-Core_v0.10.0_v-Finale.docx` also describes an iSamples Core adapter (section 4, `mapCoreToISamples`, plus crosswalks 1.1, 1.3, 1.4 and the masking rule in 5). This change adds that third format under `application/vnd.otelo.isamples+json` (the name ADR 0042 reserved), mirroring the DataCite adapter one for one: Core is the pivot, the adapter is pure `domain` code, the routes only add a media type.

Decisions taken with the user:

- `complies_with` is the constant `["https://w3id.org/isample/schema/2.0"]`.
- `keywords[]` comes from `extensions.geology.economic.interestElements` alone, per the contract; `contextCategories[]` is a deliberate drop.

Target shape: iSamples `materialSampleRecord` JSON schema 2.0 (`https://w3id.org/isample/schema/2.0`, fetched during planning). Required: `pid`, `label`, `last_modified_time`. Nested `$defs` are `additionalProperties: false`: `Agent {name, pid, affiliation, role, contact_information}`, `IdentifiedConcept {label, pid, scheme_name, scheme_uri}`, `SamplingEvent {label, description, responsibility[], result_time, project, sampling_site, sample_location, authorized_by[], has_context_category[], has_feature_of_interest, pid}`, `SamplingSite {label, description, place_name[], site_location, is_part_of[], pid}`, `GeospatialCoordLocation {latitude, longitude, elevation, obfuscated}`, `MaterialSampleCuration {label, description, access_constraints[], curation_location, responsibility[], pid}`, `SampleRelation {relationship, target, label, description}`.

## Files

New folder `packages/domain/src/sample/isamples/` (same split as `sample/datacite/`):

- `isamples-schema.ts`: `iSamplesSampleSchema` / `ISamplesSample` (every property `.meta({ description })`, the OpenAPI spec fails on an undescribed property), `ISAMPLES_MEDIA_TYPE`, `ISAMPLES_SCHEMA_URI = "https://w3id.org/isample/schema/2.0"`, and the vocabulary constants below.
- `to-isamples-sample.ts` (`toISamplesSample(core: CoreSample): ISamplesSample`): top-level assembly.
- `to-isamples-agents.ts`: `toISamplesAgent`, role crosswalk, the four role pickers (registrant, sampling responsibility, curator, authorized_by).
- `to-isamples-categories.ts`: material and context crosswalks (§1.3, §1.4) plus the constant object type.
- `to-isamples-sampling-event.ts`: `produced_by` (site, location, masking, elevation string).
- `to-isamples-sample.spec.ts`: whole-value tests on `FIELD_SAMPLE` and `SYNTHETIC_SAMPLE` via `toCoreSample(sample, FRONTEND_URL)`, plus the Core-coverage guard copied from `to-datacite-sample.spec.ts` (`PROJECTED_CORE_PATHS` / `DROPPED_CORE_PATHS` over `coreSampleSchema.shape`).

Edited:

- `packages/domain/src/service-account/service-sample-validator.ts`: `iSamplesListSamplesResponseSchema` / `ISamplesListSamplesResponse` through the existing `listSamplesResponseSchema(record, { id: "ISamplesSampleList", ... })`.
- `packages/api/src/service-account/service-route-definitions.ts`: `SERVED_MEDIA_TYPES` gains `ISAMPLES_MEDIA_TYPE`; `negotiated()` takes a `Record<mediaType, schema>` (or a third parameter) so each 200 lists three content types; the `accept` header description names the third format.
- `packages/api/src/service-account/service-routes.ts`: replace the `toDataCite` parameter of `serve()` with a map `{ [DATACITE_MEDIA_TYPE]: toDataCiteSample, [ISAMPLES_MEDIA_TYPE]: toISamplesSample }` keyed by negotiated format, the list route wrapping each in the `{ data, meta }` envelope; `application/json` stays the Core fallthrough. Keep `c.json(body, 200, { "content-type": format })`.
- `packages/api/src/service-account/service-routes.spec.ts`: the two "DataCite records under the DataCite media type" tests become `pgTest.for` over `[{ mediaType, map, listSchema, schema }]` for DataCite and iSamples; the wildcard-ranking cases stay DataCite-only.
- `packages/api/src/service-account/openapi.spec.ts`: the Accept enum expectation becomes `["application/json", DATACITE_MEDIA_TYPE, ISAMPLES_MEDIA_TYPE]`.
- `docs/isamples-mapping.md`: new, same layout as `docs/datacite-mapping.md` (status, media type, masking, Core-ordered mapping table, deviations).
- `docs/igsn-core-mapping.md` line 3 and `docs/datacite-mapping.md` line 5 (the "two other adapters out of scope" sentence): mention the iSamples format and link the new doc.
- No new ADR: ADR 0042 already decided the pivot, the negotiation and this media type name, so it stays as written.

Agent shape (`toISamplesAgent`, the schema forbids extra keys): `name` <- `joinContactName(firstname, lastname)` or the organization name; `pid` <- `agent.id` when set; `affiliation` <- affiliation names joined with `", "` when any (one string in iSamples); `role` <- §1.1 as an exhaustive `Record<CoreRole, string>`: `Creator -> collector`, `Collector -> collector`, `ChiefScientist -> chiefScientist`, `Researcher -> researcher`, `Curator -> curator`, `Registrant -> registrant`, `HostingInstitution -> hostingInstitution`.

IdentifiedConcept shape for the three iSamples vocabularies: `pid` <- `<vocabulary base><slug>`, `label`, `scheme_name`, `scheme_uri`, with bases `https://w3id.org/isample/vocabulary/material/` (scheme `.../1.0/materialsvocabulary`, "iSamples Materials Vocabulary"), `.../sampledfeature/` (scheme `.../1.0/sampledfeaturevocabulary`, "iSamples Sampled Feature Type vocabulary"), `.../materialsampleobjecttype/` (scheme `.../1.0/materialsampleobjecttype`, "iSamples Material Sample Object Type Vocabulary"). Slugs and labels come from the vocabularies fetched during planning (`isamplesorg/vocabularies`, `vocabulary/*.ttl`).

Deviations to record in the doc: `sample_location` sits on `produced_by`, not `produced_by.sampling_site` as the contract writes, because the 2.0 `SamplingSite` forbids that key (`site_location` is its own slot and stays unused); `sample_identifier` and `curation.label` / `access_constraints` / `curation_location` are our reading of the contract's `curation.*` and identity rows; a non-point geometry emits no coordinates.
