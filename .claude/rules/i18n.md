# i18n

## All content is translated

- No user-facing string is hardcoded: every label, message, error, and piece of copy goes through the translation layer.

## Controlled vocabularies are codes, not labels

- Store controlled-vocabulary values (e.g. sample nature) as stable `lower_snake_case` machine codes, never human labels.
- Prefix every domain enum's translation keys with the enum name, `<enum>_<code>` (`nature_hand_sample`), since app catalogs merge into one namespace.
- A code reused under several tree parents shares one key.

## Shared enum translations live in domain

A vocabulary is domain data, so both its text and its resolving logic live in `domain`, never in `design-system` or an app.

- Text goes in `packages/domain/messages/{locale}.json`, merged into each app via its `project.inlang/settings.json` `pathPattern`.
- The resolver is written once (e.g. `sample/create-sample-labels.ts`) and takes `m` as a parameter, since Paraglide compiles a separate `m` per app.
- Each app binds its own `m` in one line (`as unknown as Messages` cast), never copying the resolver.
- App-only copy backed by no shared enum (page text, form chrome, columns) stays in that app's catalog.
- The api's mail copy lives in `packages/api/messages/{locale}.json` and resolves with i18next, not Paraglide, since the api has no build step to generate a runtime into.
- `packages/api/src/mail/i18n.ts` owns the single `createInstance()`, and `declare module "i18next"` types the keys from the catalog, so an unknown key fails `tsc` rather than rendering raw in a mail.
- Its `escapeValue: false` is deliberate, since each mail renders twice, as plain text and as MJML, and escaping here would corrupt the text body.
- User-supplied values are therefore escaped with `escapeHtml` where they are injected into the MJML, never earlier.

## Enforce coverage at compile time

A missing translation must fail the build, not render a raw key.

- Flat vocabularies (literal union input): assert the catalog covers the enum, or use a `Record<Code, () => string>` map where the app binds `m` directly.
- Tree vocabularies (runtime `string` paths): cover them with a spec walking every path, failing on any label that is its own key.

```ts
import type Catalog from "../../messages/en.json"; // type-only, erased
type MessageKey = keyof typeof Catalog;
type AssertKeys<T extends MessageKey> = T; // errors if a key is missing
type _nature = AssertKeys<`nature_${Nature}`>;
```

## Tests use English

- All test content (input data, expected strings, fixtures, copy) MUST be in English.

## Frontend URL localization

- The public `frontend` localizes by URL: every localized route carries a language prefix (e.g. `/fr/...`).
- Every page declares a `<link rel="canonical">` to its English (base-locale) version.
- `admin` is exempt: authenticated, single locale, not indexed.
