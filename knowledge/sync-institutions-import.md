The laboratories and OSUs the app offers come from a CSV export regenerated by one command, then reviewed as a diff. Feeds [[institutional-groups]].

1. **Put four CSVs in the gitignored `sync-data/`**: `institution_organisation.csv` (`#ID`, `ror`), `institution_osu.csv` (`#ID`, `name`, `acronym`), `institution_laboratory.csv` (`#ID`, `code`, `acronym`, `name`, `#osu_id`), `institution_organisation_laboratory.csv` (`#laboratory_id`, `#organization_id`). Columns match by name, order does not matter, extras are ignored. The `#` columns only match the files with each other and none is imported; what is stored is the laboratory's `code` and the OSU's `acronym`, so ids may be renumbered between exports. The import stops on a missing or duplicated laboratory `code` or OSU `acronym`, an unquoted comma/quote/line break, or a row whose field count differs from the header.
2. **Run** `pnpm --filter @projet-igsn/domain sync-institutions` then `pnpm fmt:apply`. It ends with a count of what it wrote.
3. **Read what it skipped.** Incomplete rows are dropped rather than failing, each reported: an organisation without a ROR is skipped, a laboratory whose organismes all vanished is dropped, a laboratory referencing an unknown OSU is kept without it, and one referencing a ROR absent from `organization.ts` is kept showing a raw code. A laboratory can also lose an organisme silently when the export points at an absent row.
4. **Review the diff** of `osu.ts` and `laboratory.ts` under `packages/domain/src/institutional-group/`, then `pnpm lint:check` and `pnpm test --project @projet-igsn/domain --project @projet-igsn/admin`.
5. **If a code disappeared**, it stays on `user` and `sample` rows. The import writes the migration clearing it in both tables (`packages/api/migrations/<stamp>-clear-removed-institutions.ts`) and names the codes on stderr. A dropped laboratory clears all three columns, the trio being validated together, so the user picks a group again at their next login; a dropped OSU clears `institutional_osu` alone. Apply it with `pnpm -F @projet-igsn/api migrate`. A renamed code reads as a drop, so turn its clearing into a remap. Tests and the dev seed hardcode codes, so run `pnpm test` and `make test-e2e`.
6. **If a laboratory changed organisme or OSU**, no migration is generated and nothing revalidates a stored trio after login, so its users are stuck showing no laboratory and having every save rejected. Read the `osu` and `organizationRors` changes in the diff and clear the three columns for those users by hand, as the generated migration does.
